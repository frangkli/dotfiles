# Stacks

A stack is a chain of PRs, each based on the branch below it. Manage it with GitHub's `gh stack` extension, which records each branch's base and restacks every branch above a change in one command. It is an early release (0.2), so check what each command did, and do a step by hand when one errors (Fallback).

- **Set up:** `gh stack init --base <trunk> <bottom> ... <top>` once, bottom to top; it adopts existing branches, including ones checked out in other worktrees, and switches this checkout to the top branch. `gh stack view --json` shows the order and each branch's recorded base.
- **Worktrees:** `gh stack` restacks a branch checked out in another worktree and updates that worktree, but stops when it has uncommitted changes. Commit or stash them first.
- **Open the PRs:** open each one per steps 4 and 5, with the branch below as its base, so every PR gets its own title and body. Then link them by number, bottom to top: `gh stack link <pr> <pr> ...`. Branch names would make it open PRs with generated titles, and so would `gh stack submit` without a terminal.
- **Restack:** after a branch changes, run `gh stack rebase --upstack --no-trunk` from it; leave out `--no-trunk` only when the stack should also move onto a fresh trunk (step 4). On a conflict it exits 3: resolve it and run `gh stack rebase --continue`, or `--abort` to restore every branch.
- **Check, then push:** run the per-commit check ([commits.md](commits.md)) and the readiness check on each branch that moved, then `gh stack push`, which pushes exactly those heads; if it rejects a branch, fix it and run it again. Not `gh stack sync`: it rebases and pushes in one run, so unchecked heads reach GitHub.
- **Babysit:** work only the lowest unmerged PR ([babysit.md](babysit.md)). Its fixes change every branch above it, so restack, check and push the whole stack in the same batch, and each PR's checks restart once.
- **Merge:** bottom up, each PR through [merge.md](merge.md) on its own head. After a merge, retarget the next PR with `gh pr edit <n> --base <trunk>` if `gh pr view <n> --json baseRefName` still names the merged branch, then restack onto the trunk (`gh stack rebase`), confirm with `git log --oneline origin/<trunk>..<branch>` that each branch holds only its own commits, check and push. The next PR's head is new, so it goes back to babysitting (CI and merge.md's patch id) before it merges. Not `gh stack merge`: it can't pin each PR's head commit. If GitHub refuses a single merge because the PR is in a stack, report it.
- **Fallback:** per branch, bottom to top, `git rebase --onto <branch below> <old base> <branch>`, with the old base from `gh stack view --json`, so commits rewritten below aren't replayed. Plain git refuses a branch checked out in another worktree, so detach those first (`git -C <worktree> switch --detach`). Then check and push each branch with `--force-with-lease`.
